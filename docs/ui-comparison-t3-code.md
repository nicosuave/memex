# Native Memex compared with current T3 Code

Research date: October 4, 2026. Local evaluation; no implementation changes are proposed as already completed.

## Verdict and correction to the first pass

Memex is a coherent native history browser with local conversation continuation. It is not yet comparable to current T3 as a complete daily coding-agent interface. The important difference is continuity of work: T3 connects draft/context, execution state, requests, tools, navigation and change review through a shared runtime model. Matching its composer appearance would reproduce only a small part of that experience.

The first pass verified the latest main identifier but based most feature claims on stable documentation, a few components, and the official screenshot. It did **not** trace the current execution projections, command policy, tests, or stable-to-main changes. That was insufficient for a claim about current T3. This revision reads the actual pinned current implementation and tests, compares it with stable source, and incorporates focused test execution by the lead agent. The earlier Memex screenshots remain direct visual evidence; they are not being presented as fresh runtime verification of T3.

The deeper investigation strengthens the active-work gap, but also corrects broad recommendations: Memex already folds completed work, preserves failures, anchors disclosure expansion and caps prose width. T3's search does not jump to a matching message. Memex's archival semantics should be preserved, and its native reader should be refined rather than replaced with another message stream.

## What current implementation establishes

### 1. Transcript grouping follows execution identity, not just message appearance

Current T3 projects native items through run/attempt ancestry into timeline rows. Repeated steers remain within the initiating response; promptless restart runs stay visually connected; superseded-attempt output can collapse without hiding user messages or persistent resource cards. Reasoning joins the same work stream as tools. Presentation can settle a stranded reasoning indicator after later activity without mutating the retained provider lifecycle. These are substantive V2 changes since stable. [Projection/attempt resolution](https://github.com/pingdotgg/t3code/blob/4ee6bfd50ef4a089440d5c3662db2298da9cc50e/apps/web/src/session-logic.ts#L563-L657), [response/attempt grouping](https://github.com/pingdotgg/t3code/blob/4ee6bfd50ef4a089440d5c3662db2298da9cc50e/apps/web/src/components/chat/MessagesTimeline.logic.ts#L694-L826).

Settled work folds while a terminal response stays visible; failed work has exceptions that preserve its evidence. The passing timeline suite covers restarted responses, superseded attempts, failure visibility, active-row selection, and incremental/full-projection equivalence. It does not establish provider interoperability or whole-app performance. [Restart assertions](https://github.com/pingdotgg/t3code/blob/4ee6bfd50ef4a089440d5c3662db2298da9cc50e/apps/web/src/components/chat/MessagesTimeline.logic.test.ts#L1892-L1995), [failure assertions](https://github.com/pingdotgg/t3code/blob/4ee6bfd50ef4a089440d5c3662db2298da9cc50e/apps/web/src/components/chat/MessagesTimeline.logic.test.ts#L4745-L4860).

**Memex implication:** it already requires both `task_complete` and `final_answer` for the exact source turn, excludes aborted turns, and keeps failures outside routine folds. This is appropriate for partial archival pages. T3's last-assistant-per-run rule must not replace that stronger evidence requirement. [Existing native grouping](/Users/nico/.codex/worktrees/1a7a/memex/apps/macos/Sources/Memex/TranscriptPresentation.swift:178).

### 2. Tool details are interpreted before being rendered

Main adds shared semantic formatting and a V2 inspector: command/arguments are separate from output; recognized MCP text/resource blocks and legacy stdout/stderr envelopes are unwrapped; duplicate structured content is avoided. Omitted large output is fetched when an inspector opens, with a separate completion revision and explicit loading, unavailable, empty and error states. Stable lacks these new V2 detail files. [Formatter](https://github.com/pingdotgg/t3code/blob/4ee6bfd50ef4a089440d5c3662db2298da9cc50e/packages/client-runtime/src/work-log/itemDetail.ts#L10-L173), [fetch/render boundary](https://github.com/pingdotgg/t3code/blob/4ee6bfd50ef4a089440d5c3662db2298da9cc50e/apps/web/src/components/chat/V2ItemInspector.tsx#L95-L191).

This directly explains a useful comparison with Memex's observed Exec output: `[0].text`, `input_text`, `chunk_id` and wrapper metadata precede the useful result. Memex's general JSON renderer displays keys recursively; Find explicitly forces raw presentation to preserve exact source occurrences. [Observed tool](/tmp/memex-ui-tool.png), [native renderer](/Users/nico/.codex/worktrees/1a7a/memex/apps/macos/Sources/Memex/ToolContentRenderer.swift:155), [Find/raw boundary](/Users/nico/.codex/worktrees/1a7a/memex/apps/macos/Sources/Memex/TranscriptController.swift:698).

**Adopt:** normalize known envelopes into command/output/status, retain raw evidence on demand, and map search occurrences into presented fields. Raw fallback remains necessary for source-only matches such as markup destinations. Do not promise complete pretty-output search by merely removing the raw-mode condition. Direct tests of every T3 formatter branch were not found; lazy-fetch success was not proven by the two passing suites.

### 3. Draft, submission and queue are different state owners

T3 persists a structured draft containing text, images, uploaded file references, terminal/review/thread context and model choices. Incomplete uploads restore as explicit reattachment requirements and block Send. Main adds thread-context persistence and per-provider/per-model option memory; these are not merely additional buttons. [Draft persistence/fields](https://github.com/pingdotgg/t3code/blob/4ee6bfd50ef4a089440d5c3662db2298da9cc50e/apps/web/src/composerDraftStore.ts#L88-L241), [reattachment assertions, inspected](https://github.com/pingdotgg/t3code/blob/4ee6bfd50ef4a089440d5c3662db2298da9cc50e/apps/web/src/composerDraftStore.test.ts#L441-L531).

The major stable-to-main change is queue ownership. Stable's queue was browser-memory-only. Main sends delivery intent to authoritative V2 command policy and creates server-owned queued runs with edit/reorder/cancel/promote commands. Stop holds queued runs; explicit resume releases the hold. Capability and execution state decide whether a running submission queues, steers or interrupts/restarts; a late steer after completion becomes a new turn. These are source-backed execution semantics, not runtime-tested provider claims. [Stable queue](https://github.com/pingdotgg/t3code/blob/6c8fed35dded9ff71c5b46807125457acbb76be6/apps/web/src/queuedMessageStore.ts#L124), [current policy](https://github.com/pingdotgg/t3code/blob/4ee6bfd50ef4a089440d5c3662db2298da9cc50e/apps/server/src/orchestration-v2/CommandPolicy.ts#L119-L165), [queue creation](https://github.com/pingdotgg/t3code/blob/4ee6bfd50ef4a089440d5c3662db2298da9cc50e/apps/server/src/orchestration-v2/Orchestrator.ts#L4690-L4751), [Stop holds queue](https://github.com/pingdotgg/t3code/blob/4ee6bfd50ef4a089440d5c3662db2298da9cc50e/apps/server/src/orchestration-v2/Orchestrator.ts#L8071-L8087).

**Memex implication:** its draft is currently an in-memory string and another send is blocked while working. Persisting a draft is an immediate continuation improvement. Queue/steer is a separate runtime feature: exposing shared queue controls without ownership, Stop and recovery semantics would produce misleading UI.

### 4. Requests and reconnection have explicit lifetimes

T3 distinguishes live approvals/questions from message-based asynchronous questions and requests whose runtime can no longer respond. Asynchronous questions can remain answerable after provider exit; answering resolves the request and dispatches its reply within one event transaction. Client subscriptions resume after the latest applied event cursor. Assertions for provider-exit questions and replacement connections were inspected, not run. [Request guards](https://github.com/pingdotgg/t3code/blob/4ee6bfd50ef4a089440d5c3662db2298da9cc50e/apps/server/src/orchestration-v2/Orchestrator.ts#L6810-L6857), [answer transaction](https://github.com/pingdotgg/t3code/blob/4ee6bfd50ef4a089440d5c3662db2298da9cc50e/apps/server/src/orchestration-v2/Orchestrator.ts#L6942-L7012), [question assertions](https://github.com/pingdotgg/t3code/blob/4ee6bfd50ef4a089440d5c3662db2298da9cc50e/packages/client-runtime/src/state/threadRequests.test.ts#L62-L118), [reconnection assertion](https://github.com/pingdotgg/t3code/blob/4ee6bfd50ef4a089440d5c3662db2298da9cc50e/packages/client-runtime/src/state/threads-sync.test.ts#L1834-L1860).

**Preserve in Memex:** original request IDs, retained live sessions after navigation, failed-draft retention, and no automatic replay after uncertain delivery. These already exist. Make request availability and complete approval detail visible before considering richer request lifetime support. The current approval preview is plain input limited to eight lines. [Existing send/recovery tests](/Users/nico/.codex/worktrees/1a7a/memex/apps/macos/Tests/MemexTests/LiveConversationTests.swift:211), [preview limit](/Users/nico/Code/memex-resume-runtime/packages/sq-ui/Sources/SQACPUI/AcpComposerView.swift:843).

### 5. Navigation describes who needs to act

Current T3's classification distinguishes background work from pending approvals, questions, failures and actionable plans. The optional Working shelf is **off by default** and already existed in stable; main shares its logic and orders work by last human-authored message instead of background wake recency. An observed return to attention can raise a row without falsely reordering everything at initial mount. Settle/snooze are explicit durable actions with reverse paths and server guards, not synonyms for an idle provider. [Current classification/order](https://github.com/pingdotgg/t3code/blob/4ee6bfd50ef4a089440d5c3662db2298da9cc50e/packages/client-runtime/src/state/threadInbox.ts#L17-L149), [default](https://github.com/pingdotgg/t3code/blob/4ee6bfd50ef4a089440d5c3662db2298da9cc50e/packages/contracts/src/settings.ts#L458-L468), [lifecycle guards](https://github.com/pingdotgg/t3code/blob/4ee6bfd50ef4a089440d5c3662db2298da9cc50e/apps/server/src/orchestration-v2/Orchestrator.ts#L2500-L2758).

**Adopt in Memex first:** project the already-retained live status into existing conversation/Home rows. Current rows consume archival metadata only, so leaving the reader can hide an approval blocker. This is source-derived, not reproduced by launching work during the audit. No new shelf, snooze or automatic settling system is required to fix it. [Live state](/Users/nico/.codex/worktrees/1a7a/memex/apps/macos/Sources/Memex/LiveConversation.swift:229), [list model](/Users/nico/.codex/worktrees/1a7a/memex/apps/macos/Sources/Memex/ConversationList.swift:17).

### 6. Search is a Memex strength to preserve, not copy from T3

Current T3 searches finished user/assistant messages in undeleted, unarchived V2 projects/threads, one match per thread, user-first, bounded to 50 per environment. It excludes unimported V1 content. The sidebar prioritizes title/PR matches over content and keeps lifecycle ordering. Stable restricted assistant content to final responses; main includes finished assistant-message rows. Crucially, results contain a snippet but **no message ID**; selection navigates to the thread, not the hit. [Current query](https://github.com/pingdotgg/t3code/blob/4ee6bfd50ef4a089440d5c3662db2298da9cc50e/apps/server/src/orchestration-v2/ThreadSearch.ts#L63-L165), [result contract](https://github.com/pingdotgg/t3code/blob/4ee6bfd50ef4a089440d5c3662db2298da9cc50e/packages/contracts/src/threadSearch.ts#L16-L29), [navigation](https://github.com/pingdotgg/t3code/blob/4ee6bfd50ef4a089440d5c3662db2298da9cc50e/apps/web/src/components/Sidebar.tsx#L3129-L3139).

Memex already has exact record anchoring. Its live Reader branch omits that anchor and requests end-follow, creating a code-derived exception that was not reproduced in the UI audit. Fix that exception rather than imitating T3 search. The observed title/excerpt problem is independent: Home emphasizes conversation titles, while All conversations emphasizes project names and truncates the match. [Reader branch](/Users/nico/.codex/worktrees/1a7a/memex/apps/macos/Sources/Memex/Reader.swift:29), [Home](/tmp/memex-ui-home.png), [search](/tmp/memex-ui-search.png).

Current T3 runtime also clipped search snippets to one line in its 255-pixel sidebar, sometimes hiding the matching word. It supplied highlighted matches and useful You/Agent source labels, but does not establish a no-clipping benchmark. Memex should improve match visibility on its own merits. [Current runtime search](/tmp/t3-current-runtime-search.jpg).

### 7. Review has provenance, not just a diff-shaped panel

T3 separates branch Changes, Uncommitted, and completed-turn checkpoints; main defaults to branch Changes where stable defaulted to working-tree changes. A turn selects baseline `N−1` through checkpoint `N`; the server requires ready checkpoints on completed runs. Review annotations retain file, scope, diff side/range and selected patch in the draft, then become message context. The annotation mechanism already existed in stable; main migrates checkpoint lookup to V2 run projections. [Scope selection](https://github.com/pingdotgg/t3code/blob/4ee6bfd50ef4a089440d5c3662db2298da9cc50e/apps/web/src/components/DiffPanel.tsx#L209-L327), [checkpoint query](https://github.com/pingdotgg/t3code/blob/4ee6bfd50ef4a089440d5c3662db2298da9cc50e/apps/server/src/checkpointing/CheckpointDiffQuery.ts#L113-L180), [annotation context](https://github.com/pingdotgg/t3code/blob/4ee6bfd50ef4a089440d5c3662db2298da9cc50e/apps/web/src/reviewCommentContext.ts#L402-L455).

**Memex implication:** transcript file previews and tool diff strings are not turn review. Start with explicit current workspace/uncommitted review if this product scope is chosen; historical per-turn review requires baseline/capture/storage ownership. Sidequery's native ReviewState/ReviewFeedbackFormatter offer file/plan annotations and approve/deny feedback, not this checkpoint contract. Reuse interaction components selectively; do not represent them as an already-integrated Git review workflow.

## Native reuse boundary and buildable order

The next scope remains the existing **history → continue → leave → return → inspect** loop, but the deeper research makes clear that it needs a small amount of durable state work as well as presentation polish. Proposed dependency order:

| Order | Change and existing owner | Observable acceptance |
|---|---|---|
| 1. Interpret evidence | Extend Memex's ToolContentRenderer/projection for known command/result envelopes; retain raw disclosure and occurrence mapping for Find. Keep existing source-turn completion and failure rules. | Existing `MEMEX_UI_TOOL_OK` tool shows useful command/output initially; raw evidence remains reachable; Find highlights presented text and falls back precisely for source-only hits. Partial/aborted turns remain unfolded. |
| 2. Preserve intent and visibility | Keep exact search anchors in the live Reader path; persist the text draft by existing native conversation identity; bind retained live status into existing list/Home rows. | Relaunch restores an unsent draft without sending it; failed/uncertain sends preserve it; an early hit opens the correct record after continuation; leaving an approval-blocked conversation leaves a visible attention state. |
| 3. Complete current controls | Use consistent title-first results and readable matching excerpts; show eligible/read-only/owned-elsewhere reasons in the existing continuation area; expose full approval input on demand. Align prompt/reply/composer within one reading lane. | The result explains why it matched; unavailable Send is understandable without hover; complete approval detail can be inspected; wide/narrow transcript layouts preserve turn association. |
| 4. Expand active coding only after choosing that scope | Project capabilities/model/request state; extend the shared command boundary for structured prompt content before wiring attachments/model/steer controls. Define queue ownership, held-on-Stop and recovery semantics before exposing queue UI. | Each offered action is supported by that provider; attachments survive/recover failed submission; changing models preserves compatible settings; Stop never silently releases queued work; reconnect cannot replay an uncertain prompt. |
| 5. Add explicit review scope | Begin with current workspace/uncommitted changes and selected evidence sent back to the draft. Add per-turn snapshots only with actual capture/storage. | A review clearly identifies which changes it compares; selected file/range/context reaches the prompt; historical turn review never substitutes the present working tree. |

Orders 1–3 are a coherent next implementation scope within Memex's present product. Orders 4–5 are additional coding-client scope, not implied authorization to implement them now.

**What can be reused:** `AcpComposerView` already accepts queue rows, steering, context chips, mentions and request panels. Sidequery's AgentInspectorView demonstrates structured submission, attachment capability checks and retention until acceptance. `AgentConversationService` supports capability-gated steer/model/configuration and command identity. **What is missing:** its current `perform` prompt boundary accepts string content with `contextRefs: []`; Memex further narrows the adapter to prompt/cancel/approval/input and lacks the richer projected state. UI bindings alone cannot provide attachment, queue or request-lifetime parity. [Shared controls](/Users/nico/Code/memex-resume-runtime/packages/sq-ui/Sources/SQACPUI/AcpComposerView.swift:142), [Sidequery consumer](/Users/nico/Code/memex-resume-runtime/apps/sidequery/Sources/mdnb/Agent/AgentInspectorView.swift:1063), [service boundary](/Users/nico/Code/memex-resume-runtime/packages/sq-acp/Sources/SQACPHost/AgentConversationService.swift:422), [Memex adapter](/Users/nico/.codex/worktrees/1a7a/memex/apps/macos/Sources/Memex/InAppAgentRuntime.swift:190).

**What should not be replaced:** Memex owns its NSTableView transcript and historical find/paging semantics. It already has an 800-point content cap and clicked-disclosure anchoring. The visible wide-layout problem comes from user content aligning to the window's right edge while assistant content aligns left; merely adding another max-width is not the fix. T3's shared conversation/composer reading lane is the useful pattern. Sq-ui's AcpMessageStreamView has a different message/tail-follow model and would require a separate integration decision. [Native width/alignment](/Users/nico/.codex/worktrees/1a7a/memex/apps/macos/Sources/Memex/TranscriptController.swift:696), [T3 reading lane](https://github.com/pingdotgg/t3code/blob/4ee6bfd50ef4a089440d5c3662db2298da9cc50e/apps/web/src/index.css#L901-L907).
