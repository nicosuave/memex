After both research trees finish, combine their `t3/findings.json`, `t3/report.md`, `codex/findings.json`, and `codex/report.md` into `findings.json`, `report.md`, `index.html`, and a short `README.md` in this directory. Root owns `serve.ts`; do not edit it without reporting why. All output stays local/uncommitted. No product implementation or public publishing.

Reader question: after the implemented capability expansion, what is Memex still missing, and what should matter next? Lead with a useful answer and ranked concrete workflows. Do not convert optional feature differences into automatic requirements, or call all broad categories missing. Explicitly distinguish actual defects, missing workflows, partial implementations, present capabilities, validation-only gaps, intentional exclusion, and uncertain comparator behavior. Priorities are judgment, not measured user impact. Preserve provider/host/build gates.

Reconcile equivalent findings across comparators into one capability where possible. Retain links to raw finding IDs and source evidence. Do not erase conflicting dispositions; resolve from supplied evidence or flag them to root. A feature discovered in only one comparator must not silently become absent from the other. Do not fabricate negative comparisons to fill empty cells. All material claims need source pointers. Add an honest scope/coverage and validation section; this is a source inventory, not a new end-to-end test campaign. Prior live queue test is a narrow existing observation, not full app certification.

Report web app: polished readable local-first, filterable comparison table/cards with text search and filters for status, category, comparator, priority; default view should focus on actionable gaps, with an obvious All findings view. Each finding should expose both comparator and current Memex behavior, user impact, recommendation, confidence, validation level, source version and clickable evidence. Prefer source links to immutable GitHub lines for public code; installed Codex evidence gets exact local source path + symbol/anchor and version/hash, without copying large proprietary sections. Build/version/scope limits visible. Include a print-friendly report and direct link to Markdown/JSON. Do not use external CDNs/network libraries, telemetry, public source uploads, invented completeness scores, nested scrolling containers, or purely decorative charts.

Accessibility: semantic controls with labels, keyboard-accessible expansion and filters, visible focus, sufficient contrast and responsive narrow viewport. A single HTML file embedding sanitized JSON is suitable; use textContent for evidence strings and escape any JSON closing script delimiters. Root will serve it with `bun serve.ts` on localhost4782 and inspect real browser behavior.

Acceptance: no dropped source findings without a reason/mapping; no stale pre-expansion conclusions; priorities are grounded; source links and filters work; JSON parses, unique IDs, all rows contain evidence and status; no fabricated cross-product parity counts; report clearly says what remains unresolved. Return compact headline findings, reconciliation decisions, output paths, and checks run.
